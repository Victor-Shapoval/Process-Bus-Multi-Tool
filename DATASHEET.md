# Process Bus Multi Tool — Protocol Datasheet

This document describes the protocol subset actually implemented by PBMT. It is not a declaration of full compliance or an IEC/IEEE certificate.

The Publisher sections describe frames generated by the configured application services. Low-level codecs can represent additional fields or data types that are not exposed by those services. All multibyte wire integers use network byte order unless stated otherwise.

## Common GOOSE/SV Behavior

- Both protocols use raw Ethernet capture/injection through `libpcap`. Untagged frames and one IEEE 802.1Q tag (`0x8100`) are supported; stacked VLAN tags are not decoded.
- Publisher VLAN settings are `vlan_id: 0..4094` and `vlan_pri: 0..7`. A VLAN tag is emitted only when `vlan_id` is present; PCP defaults to `4`, and DEI is `0`.
- The MAC and APPID ranges below are enforced by project validation by default. Per-stream `allow_nonstandard: true` permits other 48-bit destination MAC addresses and 16-bit APPIDs. For Subscribers, `match_any_app_id: true` disables APPID matching and its range check.
- Omitting a Subscriber VLAN filter accepts both tagged and untagged frames. Setting `vlan_id`, including `0`, requires a matching tagged frame.
- Multiple publications/subscriptions are supported. Subscriber matching stops at the first matching subscription for a received GOOSE PDU or SV ASDU.

### Publisher

#### Ethernet and APDU

| Field | Size | Transmitted value |
| --- | ---: | --- |
| Destination MAC | 6 bytes | `dst_mac` |
| Source MAC | 6 bytes | `src_mac` |
| TPID | 2 bytes | `0x8100` when VLAN is configured |
| PCP / DEI / VID | 3 / 1 / 12 bits | `vlan_pri` / `0` / `vlan_id` |
| EtherType | 2 bytes | `0x88B8` |

#### goosePDU

| Tag | Field | Format | Transmitted value |
| --- | --- | --- | --- |
| `0x80` | `gocbRef` | VisibleString | `gocb_ref` |
| `0x81` | `timeAllowedToLive` | Unsigned | `max_interval_ms`, ms |
| `0x82` | `datSet` | VisibleString | `dat_set` |
| `0x83` | `goID` | VisibleString | `go_id` |
| `0x84` | `t` | UtcTime, 8 bytes | Time of the last state change |
| `0x85` | `stNum` | Unsigned | State number; initial value is `1` |
| `0x86` | `sqNum` | Unsigned | Message number within the current state |
| `0x87` | `test` | Boolean | Test flag from Manual |
| `0x88` | `confRev` | Unsigned | `conf_rev` |
| `0x89` | `ndsCom` | Boolean | `nds_com` |
| `0x8A` | `numDatSetEntries` | Unsigned | Number of `allData` elements |
| `0xAB` | `allData` | SEQUENCE OF Data | DataSet values in configured order |

`t` and `utc_time` elements are transmitted as 32-bit seconds, a 24-bit fractional second, and one TimeQuality byte:

| TimeQuality bits | Field |
| --- | --- |
| 7 | `leapSecondsKnown = 0` |
| 6 | `clockFailure = 0` |
| 5 | `clockNotSynchronized`: `1` when the internal clock is not synchronized by PTP |
| 4..0 | `timeAccuracy = 31` (`unspecified`) |

The Publisher captures `t` and TimeQuality at initialization and on a DataSet/Test/Simulation change. Retransmissions retain them; a PTP synchronization change alone does not refresh these fields or increment `stNum`. An automatic `utc_time` value is resolved to that state-change time; an explicit timestamp is retained, with TimeQuality supplied by the application clock.

#### allData Types Available to the Publisher

| Project type | BER Data | Tag | Wire format |
| --- | --- | --- | --- |
| `bool` | BOOLEAN | `0x83` | `0x00` / `0xFF` |
| `quality` | BIT STRING | `0x84` | IEC 61850 Quality, 14 significant bits |
| `int` | INTEGER | `0x85` | Signed BER integer, up to 64 bits |
| `uint` | UNSIGNED | `0x86` | Non-negative BER integer, up to 64 value bits; leading `0x00` when needed to protect the sign |
| `float` | FLOATING_POINT | `0x87` | Exponent width `8` + IEEE 754 binary32 |
| `string` | VISIBLE_STRING | `0x8A` | String bytes |
| `utc_time` | UTC_TIME | `0x91` | UtcTime, 8 bytes |

GOOSE Quality uses an MSB-first ASN.1 BIT STRING: one unused-bits octet (`2`) followed by two payload octets holding 14 significant bits. It is not the raw UINT32 representation used by SV.

#### Counters and Transmission

| Event | `stNum` | `sqNum` | Interval |
| --- | ---: | ---: | --- |
| First frame | `1` | `0` | Immediately after startup |
| DataSet, Test, or Simulation change | `+1` | `0` | Immediately |
| Retransmission after a change | Unchanged | `+1` | `min_interval_ms`, then doubled up to `max_interval_ms` |
| Steady state | Unchanged | `+1` | `max_interval_ms` |

Applying an unchanged state does not increment `stNum`. Both counters skip `0` on UINT32 rollover; `sqNum=0` is reserved for the first frame of a state. The advertised `timeAllowedToLive` remains `max_interval_ms` during both rapid retransmission and steady state.

### Subscriber

#### Received Fields

The Subscriber decodes Ethernet/VLAN, APPID, Simulation, and every `goosePDU` field listed for the Publisher.

| goosePDU field | Decoding status |
| --- | --- |
| `gocbRef` | Required |
| `timeAllowedToLive` | Required |
| `datSet` | Required |
| `goID` | Optional |
| `t` and TimeQuality | Required; UtcTime must be exactly 8 bytes |
| `stNum` | Required |
| `sqNum` | Required |
| `test` | Optional |
| `confRev` | Required |
| `ndsCom` | Optional |
| `numDatSetEntries` | Required; must equal the number of `allData` elements |
| `allData` | Required |

The decoder rejects duplicate known `goosePDU` fields, missing required fields, truncated APDUs, and inconsistent APDU/BER lengths. Ethernet padding outside the declared APDU is allowed. Only definite BER lengths are supported. Unsigned values must use a minimal non-negative BER integer encoding; protocol counters are limited to UINT32.

#### Decoded allData Types

| BER Data | Tag |
| --- | --- |
| ARRAY | `0xA1` |
| STRUCTURE | `0xA2` |
| BOOLEAN | `0x83` |
| BIT STRING | `0x84` |
| INTEGER | `0x85` |
| UNSIGNED | `0x86` |
| FLOATING_POINT | `0x87` |
| REAL | `0x88` |
| OCTET_STRING | `0x89` |
| VISIBLE_STRING | `0x8A` |
| BINARY_TIME | `0x8C` |
| BCD | `0x8D` |
| BOOLEAN_ARRAY | `0x8E` |
| UTC_TIME | `0x91` |

Arrays and structures are decoded recursively. FLOATING_POINT accepts exponent-width-prefixed IEEE 754 binary32 or binary64. The `REAL` tag is routed through the same decoder; general ASN.1 REAL encodings are not implemented. BINARY_TIME is retained as raw bytes. Unknown Data types are retained as raw bytes for diagnostics. Recognizing a tag does not imply complete validation of every value encoding.

#### Subscription Filters

| Field | Matching rule |
| --- | --- |
| Destination MAC | Required exact match |
| Source MAC | Exact match or any source |
| APPID | Exact match, including `0x0000`, or `match_any_app_id` |
| `gocbRef` | Exact match or any value |
| `datSet` | Exact match or any value |
| `goID` | Exact match or any value |
| `confRev` | Exact match or any value |

#### Stream State and Diagnostics

- Accepted frames update the latest values and the `timeAllowedToLive` watchdog. Duplicate or reordered counter pairs and frames with an older state-change timestamp are ignored and do not refresh the watchdog.
- Counter comparisons account for UINT32 wraparound. A backward `stNum` is accepted as a restart only with `sqNum=0` and a newer timestamp, unless either timestamp is absent.
- The service reports first reception, state/revision changes, publisher restart, stream loss/restoration, and sequence gaps. Stream loss is detected after the last accepted frame's `timeAllowedToLive` expires.
- Project ICD metadata supplies signal names only when stream identity, revision, and DataSet structure match. Otherwise, positional entry labels are used.

#### savPDU and ASDU

| Tag | Field | Size | Transmitted value |
| --- | --- | ---: | --- |
| `0x60` | `savPDU` | variable | Sampled Values container |
| `0x80` | `noASDU` | variable BER Unsigned | `1` |
| `0xA2` | `seqASDU` | variable | ASDU sequence |
| `0x30` | ASDU | variable | One ASDU per Ethernet frame |
| `0x80` | `svID` | variable | `sv_id` |

The Publisher does not transmit the optional `datSet [0x81]`, `refrTm [0x84]`, `smpRate [0x86]`, or `smpMod [0x88]` fields. `dat_set` is used only when exporting SCL/ICD.

For a 10-byte `svID`, APDU Length is `108` (122 bytes including an untagged Ethernet header, or 126 bytes with VLAN; excluding FCS).

The low-level SV codec can encode multiple ASDUs and optional ASDU fields, but the running 9-2LE Publisher emits the single-ASDU format above.

#### Transmission Rate

| `smp_rate` | `sample_timing_frequency` | Frames/s | `smpCnt` range |
| ---: | ---: | ---: | --- |
| 80 | 50 Hz | 4000 | `0..3999` |
| 80 | 60 Hz | 4800 | `0..4799` |

Project validation permits only `smp_rate: 80` for the Publisher. The first frame is scheduled at the next whole application-clock second with `smpCnt=0`. Scheduling follows the shared application clock, including PTP frequency correction. If a sample slot is missed, the sample counter and waveform phase advance past it; stale samples are not sent in a catch-up burst. Frame rate and timing statistics are software measurements, with no hard real-time guarantee.

#### Waveform and Synchronization

- Each channel has independent RMS, phase angle, frequency, and Quality. Samples are rounded from `RMS × sqrt(2) × sin(phase)`, using the channel's raw scale. RMS must be finite and non-negative, phase finite, and frequency positive and no greater than half the configured sample rate in samples/s. Settings that would overflow INT32 are rejected.
- RMS is expressed in secondary amperes/volts. `Ua`, `Ub`, and `Uc` are phase-to-neutral voltages. Changing waveform frequency does not change the Ethernet frame rate.
- Simulation and `smpSynch` are transmitted as selected. `smpSynch` is not automatically derived from PTP lock status; setting it does not synchronize the clock.

### Subscriber

#### Received ASDU Fields

| Tag | Field | Status | Format |
| --- | --- | --- | --- |
| `0x80` | `svID` | Required | Non-empty string |
| `0x81` | `datSet` | Optional | String |
| `0x82` | `smpCnt` | Required | UINT16 |
| `0x83` | `confRev` | Required | UINT32, exactly 4 bytes |
| `0x84` | `refrTm` | Optional | UtcTime, 8 bytes total, including TimeQuality |
| `0x85` | `smpSynch` | Required | `0..2` |
| `0x86` | `smpRate` | Optional | UINT16 |
| `0x87` | `seqData` | Required | Exactly 64 bytes for 9-2LE |
| `0x88` | `smpMod` | Optional | UINT16: `0` samples/period, `1` samples/s, `2` seconds/sample |

Multiple ASDUs in one frame are supported; the count is checked against `noASDU`. The live decode path rejects missing required ASDU fields, empty `svID`, incorrect lengths of the fixed-size ASDU fields above, invalid `smpSynch`/`smpMod`, truncated containers, and ASDU count mismatches. A separate diagnostic decoder can return partial data with warnings; such damage is not accepted for live measurements. Unknown ASDU tags generate diagnostic warnings but do not by themselves reject a frame.

#### Subscription Filters

| Field | Matching rule |
| --- | --- |
| Destination MAC | Required exact match |
| Source MAC | Exact match or any source |
| APPID | Exact match, including `0x0000`, or `match_any_app_id` |
| `svID` | Exact match or any value |
| VLAN ID | Exact match or no filter |

There are no subscription filters for PCP, `confRev`, Simulation, `smpSynch`, or Quality. These fields are observed rather than used to reject otherwise matching samples.

#### Measurements and Continuity

- Subscriber configuration accepts `smp_rate: 80|256` and `sample_timing_frequency: 50|60`. A nonzero received `smpRate` overrides the configured samples-per-period value; otherwise the configured value is used.
- The codec decodes all three `smpMod` values, but the measurement service still treats the effective `smpRate` as samples per period. Rate conversion for samples/s or seconds/sample modes is not implemented.
- The service calculates per-channel RMS, phase, and frequency and exposes instantaneous values and Quality. The display uses a configurable base vector and `current_coefficient` / `voltage_coefficient` scaling.
- Duplicate or reordered samples are ignored. A forward `smpCnt` gap, `confRev` change, or restoration after loss resets measurement windows. Diagnostics track missed samples, synchronization changes, and stream loss/restoration.
- A stream is marked lost after more than 100 ms without an accepted sample, checked periodically by the watchdog.

## PTP

| Parameter | Default Profile | IEEE C37.238 Power Profile |
| --- | --- | --- |
| Version | IEEE 1588-2008 / PTPv2 | IEEE 1588-2008 + C37.238-2011 or C37.238-2017 |
| Transport | UDP/IPv4 or Ethernet L2 | Ethernet L2 only |
| Delay mechanism | E2E or P2P | P2P only |
| `transportSpecific` | `0` | `0` |
| Domain | `0..255`, default `0` | `0..255`, set by configuration |
| Sync interval | 1 s | 1 s |
| Announce interval | 2 s | 2 s |
| Delay/PDelay interval | 1 s | 1 s |
| Announce receipt timeout | 6 s | 6 s |

These intervals are the implemented profile values. The Client receives the external master's Sync/Announce traffic; the table does not require the remote source to transmit at those exact intervals. Its Sync-loss threshold is 3 s and foreign-master expiry is 6 s, with periodic timeout checks.

### Platform and Timestamp Support

| Mode | Linux | macOS |
| --- | --- | --- |
| External Client, Ethernet L2 | Hardware timestamps attempted first; kernel software fallback | Software timestamps from libpcap/BPF, including the captured outgoing frame for TX |
| External Client, UDP/IPv4 | Hardware timestamps attempted first; kernel software fallback | Unavailable: the implemented transport cannot obtain the required UDP TX timestamp |
| Server, Ethernet L2 or UDP/IPv4 | Hardware-only; requires PHC and `PTP_SYS_OFFSET_PRECISE` | Unavailable |
| Local Client | Internal binding to a running PBMT Server | Unavailable in practice because the local Server cannot start |

Power Profile transport remains Ethernet-only. Client timestamp selection is automatic; the legacy `timestamp_mode` YAML field is accepted but discarded. Event exchanges require transport-provided RX/TX timestamps. Missing timestamps cause the packet/exchange to be rejected or the transport to fail; no `time.Now()` replacement is used for a missing packet timestamp.

### PTP Client

#### Clock Source

| `source` | Behavior |
| --- | --- |
| `external` | Slave-only network client; selects a qualified Grandmaster and disciplines PBMT's internal application clock |
| `local` | Binds directly to the running PBMT PTP Server's clock; no PTP packets, BMCA, network-delay measurement, or servo exchange |

The host system clock is never adjusted. Omitted `source` defaults to `external`. Local mode requires starting the Server first and ignores the retained network settings. If the local source is lost, the application clock enters unsynchronized holdover and the Client reports an error; restart the Client after restoring the Server. There is no automatic switching between Local and External.

The message tables below describe External mode.

#### Received Messages

| Message | Channel | Received body fields |
| --- | --- | --- |
| `ANNOUNCE` | General | `originTimestamp`, `currentUtcOffset`, `grandmasterPriority1`, `clockClass`, `clockAccuracy`, `offsetScaledLogVariance`, `grandmasterPriority2`, `grandmasterIdentity`, `stepsRemoved`, `timeSource`, TLV |
| `SYNC` | Event | `originTimestamp`; the RX timestamp is obtained from the transport |
| `FOLLOW_UP` | General | `preciseOriginTimestamp` |
| `DELAY_RESP` | General | `receiveTimestamp`, `requestingPortIdentity` |
| `PDELAY_REQ` | Event | `originTimestamp`, 10 reserved bytes; the Client responds as a P2P peer |
| `PDELAY_RESP` | Event | `requestReceiptTimestamp`, `requestingPortIdentity`; the RX timestamp is obtained from the transport |
| `PDELAY_RESP_FOLLOW_UP` | General | `responseOriginTimestamp`, `requestingPortIdentity` |

Only PTPv2 messages with matching `domainNumber` and `transportSpecific` values are accepted. Messages sent by the local port are ignored. Event messages without a transport timestamp are ignored.

For Grandmaster selection, `ANNOUNCE` must contain the `PTP_TIMESCALE` and `CURRENT_UTC_OFFSET_VALID` flags. Qualification requires at least two distinct Announce sequence IDs within four advertised Announce intervals (using the profile interval when the advertised value is unusable). BMCA compares Priority1, ClockQuality, Priority2, and GrandmasterIdentity across different Grandmasters; for the same Grandmaster it compares StepsRemoved and port identities.

The Client accepts both one-step Sync and two-step Sync/FollowUp. FollowUp matching uses source port identity and sequence ID, with bounded buffering for FollowUp arriving before Sync. P2P accepts one-step and two-step peer-delay responses. Offset and path-delay processing includes correction fields. The PI servo adjusts only the application clock, with frequency correction limited to ±500,000 ppb (±500 ppm).

#### Transmitted Messages

| Mechanism | Message | Channel | Transmitted body fields |
| --- | --- | --- | --- |
| E2E | `DELAY_REQ` | Event | `originTimestamp` |
| P2P | `PDELAY_REQ` | Event | `originTimestamp`, 10 reserved bytes |
| P2P peer response | `PDELAY_RESP` | Event | `requestReceiptTimestamp` (t2), `requestingPortIdentity`, `TWO_STEP` |
| P2P peer response | `PDELAY_RESP_FOLLOW_UP` | General | `responseOriginTimestamp` (t3), `requestingPortIdentity` |

The request `originTimestamp` is filled from the application clock before sending; delay calculations use the actual transport TX timestamp. The Client's peer responses are two-step. The Client does not advertise itself as a Grandmaster.

| --- | --- |
| C37.238-2011 | `organizationId=1C:12:9D`, `organizationSubType=00:00:01`, `grandmasterID`, `grandmasterTimeInaccuracy`, `networkTimeInaccuracy`, `reserved` |

### PTP Server

The Server operates only as a Forced Grandmaster and always uses two-step time transfer.

It does not run BMCA to yield to another master. Advertised clock quality, traceability, UTC offset, and Power Profile inaccuracy values are configured properties, not measured accuracy guarantees.

#### Transmitted Messages

| Message | Channel | Transmitted body fields |
| --- | --- | --- |
| `ANNOUNCE` | General | `originTimestamp`, `currentUtcOffset`, `priority1`, `clockClass`, `clockAccuracy`, `offsetScaledLogVariance`, `priority2`, `grandmasterIdentity`, `stepsRemoved=0`, `timeSource`, optional TLVs |
| `SYNC` | Event | `originTimestamp=0`, `TWO_STEP` flag; the precise TX timestamp is obtained from the transport |
| `FOLLOW_UP` | General | `preciseOriginTimestamp` from the corresponding `SYNC` TX timestamp |
| `DELAY_RESP` | General | `receiveTimestamp` (t4), `requestingPortIdentity`; `sequenceId`, `domainNumber`, and `correctionField` are associated with the request |

| `PDELAY_RESP_FOLLOW_UP` | General | `responseOriginTimestamp` (t3), `requestingPortIdentity`, `correctionField` from the request |

It is not emitted by the Default Profile. The configured alternate offset is advertised metadata; it does not shift the application clock.

The PTP Server starts only on Linux when hardware timestamping, a PHC, and `PTP_SYS_OFFSET_PRECISE` are available. It takes the host UTC epoch once at startup, then advances from `CLOCK_MONOTONIC_RAW`, mapping PHC packet timestamps into that autonomous timescale. Subsequent system-clock changes do not step its timescale. Server wire timestamps use TAI; `currentUtcOffset` specifies TAI−UTC. This is a laboratory Grandmaster, not a reference time source.

## MMS and SCL/ICD

| Capability | Implemented behavior |
| --- | --- |
| Transport | MMS over ISO-on-TCP through bundled `libiec61850`; configurable IP/port, default TCP `102` |
| Model discovery | Logical devices, logical nodes, functional-constraint groups, nested structures/arrays, and MMS type widths |
| DataSets | Reads directory and ordered membership |
| GOOSE control blocks | Reads DataSet reference, GoID, ConfRev, destination MAC, APPID, VLAN/priority, MinTime, and MaxTime |
| Report control blocks | Reads buffered/unbuffered report configuration, trigger options, and optional-field settings |
| Setting groups | Reads `NumOfSG` and `ActSG` from `LLN0$SP$SGCB` |
| Live values | Polls visible attributes at a nominal 1 s interval using MMS reads; array/structure elements are selected from the returned variable |
| Timeouts | 3 s connection timeout; 2 s per MMS request |
| ICD export | Reconstructs an SCL model from discovered types, DataSets, and supported control metadata |

The PBMT adapter is read-only: it does not expose MMS writes, control operations, setting-group changes, or report subscriptions. Reading report configuration does not enable report delivery. Native request duration and the number of visible variables can lengthen a polling cycle.

Online ICD reconstruction infers CDCs from structure; enumeration labels and engineering descriptions are unavailable. Unsupported objects, unresolved DataSets, and dependent control blocks are omitted with warnings. The result does not replace a manufacturer's engineering file. Separately, PBMT can import GOOSE publication metadata from SCL, resolve received GOOSE entries against a project ICD, and export SCL for its own GOOSE/SV publications. SCL import does not provide a source MAC address.

## MCP Automation Interface

PBMT exposes prepared GOOSE/SV streams over authenticated Streamable HTTP at `/mcp`, using `Authorization: Bearer <token>`. Tools support status/catalog reads, live values, Publisher changes, timed sequences, and an SV-stimulus-to-GOOSE-edge response-time test. MCP does not start protocol modules or expose PTP control.

While MCP is active, Manual control is locked. Agent connection loss cancels work and stops GOOSE/SV Publishers. Stop MCP returns control to Manual; ordinary sequences retain their last outputs, while response-time tests reset affected channel RMS values to zero and require confirmation that a reset frame was sent. If reset cannot be confirmed, control is revoked and both GOOSE/SV Publishers are stopped. Response-time measurements use software timestamps and include driver/capture delays; they are not NIC hardware measurements or hard real-time guarantees.

See [MCP.md](MCP.md) for tool schemas, timing limits, control handover, and failure behavior.
